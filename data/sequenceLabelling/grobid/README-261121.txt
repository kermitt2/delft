DeLFT training data without the commonName feature (GROBID issue #1454), generated 2026-11-21 by the GROBID
trainers (AbstractTrainer.createCRFPPData) from branch feature/remove-common-name @ 824962f15.

The commonName column is still present (layout unchanged) but is 0 on every row of every file:
  header col 21, reference-segmenter col 16, citation col 15, affiliation-address col 15,
  name-header col 14, name-citation col 14, patent-citation col 14   (col 0 = token, last col = label)

<model>.train = the corpus/ data, <model>.test = the evaluation/ data (small for header/name-header, see counts).

Default in grobid-full.yaml: header ChainCRF, reference-segmenter ChainCRF, citation CRF, affiliation-address,
patent-citation. The others are shipped but not used by default.
Embeddings: glove-840B. Not affected (do not retrain): date, figure, funding-acknowledgement.
The header-article-light(-ref) DL models also read the column; they are handled on the light-models branch
(PR 1654) once the column is zeroed there.

DeLFT 0.4.7 (what GROBID calls through DeLFTModel.train), from the DeLFT root, e.g.:
  python3 delft/applications/grobidTagger.py header train \
      --input header.train --output <out dir> \
      --architecture BidLSTM_ChainCRF_FEATURES --max-sequence-length 3500 --batch-size 9
Optionally evaluate with the .test file (train_eval / eval with --input <model>.test).
Then copy <out dir>/<model>-<ARCH>/ (config.json, model_weights.hdf5, preprocessor.json) over
grobid-home/models/<model>-<ARCH>/ on branch feature/remove-common-name.
